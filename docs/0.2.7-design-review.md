# Delta Harness 0.2.7 design review

Reviewed against the working tree after the safe/trusted profile and budget-signal commits, plus targeted competitor source under `~/delta/.refs`. The recommendation below keeps the 0.2.7 default behavior equivalent to 0.2.6 and adds no runtime dependency.

## Risk ranking

| Rank | Item | Risk | Release call |
|---:|---|---|---|
| 1 | 1. Profiles + envelope | Permission-boundary and compatibility regression | Ship after malformed-input and safe-mode isolation tests |
| 2 | 5. Safe-mode boot + revert | A recovery path that shares normal boot inputs can fail exactly when needed | Ship a hard, explicit recovery branch; reuse existing revert machinery |
| 3 | 4. Resilience trio | A truncated but parseable call can execute an unintended side effect; retry policy can waste quota | Ship the output-cap guard and small classifier; keep repair conservative |
| 4 | 6. Local skills | Prompt supply-chain, path confinement, and read/write-capability mismatch | Ship only the read-only, restart-loaded adapter |
| 5 | 3. Turn-failure integrity | Durable effects can be hidden by a failed transcript | Ship an effect-aware budget failure; retain `failed` status |
| 6 | 7. Status surface | Secret/tenant leakage, shape drift, and ambiguous usage under concurrency | Fix the current static projection; make usage run-addressable |
| 7 | 2. Budget signal | Low-risk prompt/cache behavior | Simplify the current repeating note to a one-shot note |

## 1. Safe/trusted tiers, envelope knob, and fail-safe

**VERDICT: FIX (the current implementation is close).**

The canonical objects and alias resolver are lean: `safe` and `trusted` are the only profile objects, while `chat` and `work` resolve through one alias map (`src/profiles.ts:20-52`). `getProfile` resolves both the ceiling and request before calling `isSubset`, so `isSubset` itself should remain a profile-to-profile function; making it parse strings would duplicate responsibility (`src/profiles.ts:66-74`, `src/profiles.ts:96-99`). Existing `DELTA_PROFILE=work` deployments resolve to the trusted object and retain the old tools and budgets. The config default changed from `work` to the behavior-equivalent `trusted` (`src/config.ts:242-249`).

Lean plan:

1. Keep the alias map + single resolver. If `PROFILES` is a supported public API and `PROFILES.work` must also survive, use shared references, not copied objects: `const safe = {...}; const trusted = {...}; export const PROFILES = {safe, trusted, chat: safe, work: trusted}`. Otherwise the current private alias map is smaller.
2. Keep the unconfigured default **trusted for 0.2.7**. Moving it to safe would silently remove code, delegation, writes, most MCP actions, 90 steps, and most budget from every deployment that relied on the prior default. That violates the release's no-behavior-change constraint. A safe default is appropriate only for a new-major/default migration with an explicit warning period.
3. Make `envToolList` all-or-nothing. It currently treats only an empty parsed list as malformed; a mixed or syntactically invalid list is accepted (`src/profiles.ts:55-64`, `src/profiles.ts:100-111`). After split/trim/dedupe, require every name to match the model/tool registry name grammar (`^[A-Za-z0-9_-]{1,128}$`). Set-but-empty **or any invalid member** returns the safe floor list. Unknown but syntactically valid names safely match no registered tool.
4. Decide and test the envelope semantic explicitly. The current post-selection replacement means an operator can set `DELTA_PROFILE=safe` and then add `remember` or `code` through `DELTA_ALLOWED_TOOLS`; the returned object is still named `safe` (`src/profiles.ts:96-111`). That is acceptable only if the env knob is documented as an operator-owned **replacement**. If “NARROW” is the invariant, intersect the override with `selected.allowed` and intersect pins with the final allowed set. My recommendation is intersection because it keeps `safe` truthful and makes the permission ordering easy to audit. Use `trusted` plus an allowed list for arbitrary custom envelopes.
5. Do not reuse normal env overrides in `DELTA_SAFE_MODE`; safe mode must select an unoverrideable clone of the safe floor (item 5).

Correctness traps:

- `DELTA_PINNED_TOOLS` can name tools outside `allowed`; the run already filters explicit pins through `allowedMap`, so no second filtering layer is required (`src/run.ts:298-321`).
- Canonical `profile.name` changes from `work` to `trusted`. Tool/budget behavior is unchanged, but any external consumer comparing the returned name is an observability/API migration. Preserve raw configured text only where it is explicitly presentation data; use the canonical name in the new status endpoint.
- Add tests for old and new names in both ceiling/request positions, empty/malformed env, pin-outside-allowed, and `DELTA_PROFILE=work` with no overrides. The current alias/envelope tests cover the main happy paths but intentionally allow a safe-tier expansion (`test/profiles.test.ts:19-52`).

## 2. Budget and context self-awareness

**VERDICT: SIMPLIFY.**

The correct placement is a synthetic, ephemeral user message at the tail of the existing ephemeral block. The stable system spine is deliberately cache-resident, whereas dynamic context/instructions/retrieval/plan already ride user messages (`src/run.ts:653-725`). Appending a dynamic system note would change the cached prefix and give an advisory too much authority.

The current implementation uses the same step/fresh-token/cost values as the hard guard and emits no raw counters, which is correct (`src/run.ts:639-650`, `src/run.ts:727-738`). It does, however, append the note on **every** model call after 85%, contrary to “doesn't bloat every step.”

Minimal fix:

- Add `let budgetWarned = false` beside `stepCount` (`src/run.ts:590-603`).
- At the existing insertion point, append the fixed qualitative note only when `budgetFrac >= 0.85 && !budgetWarned`, then set the flag. A process restart may re-warn once; that is harmless and avoids new persistence.
- Keep it last, after the plan, so it is recent without entering the system spine. Do not add it to SQLite, compaction, `remainingBudget()`, or every tool result.
- Test three calls around the threshold, assert exactly one wire note, and assert no message row contains it.

One-shot is the useful compromise: the model sees the advisory before choosing its next action, and its ensuing assistant/tool turn reflects that choice. Repeating it buys little and steadily moves the cache tail.

## 3. Turn-failure integrity

**VERDICT: FIX.**

What actually happens is narrower than “drops run rows.” On failure, `finalize` marks this run's non-user message rows inactive and inserts one clean assistant failure; it does **not** delete messages, journal rows, call captures, or the run row (`src/run.ts:1308-1339`). Future active context therefore loses the assistant tool intent and tool result, but diagnostics retain them. `store:false` later deletes transcript/run/journal/call rows, while intentionally retaining cross-run `self_revisions` and `thread_state` (`src/queue.ts:442-460`).

`remember` commits before its tool result is journaled: `writeSelf` atomically renames the file, then snapshots the prior content (`src/self.ts:108-151`); the builtin reports success as a normal tool value (`src/builtins.ts:620-653`). A later budget failure currently returns only the budget string (`src/run.ts:639-650`, `src/run.ts:781-788`), so the durable effect becomes invisible in the active conversation.

Minimal fix:

1. Keep the run status `failed`. A side effect landing does not mean the requested outcome completed; changing the status would lie to retries, task pollers, and reflection.
2. On the two budget-failure paths only, build the failure text with a bounded `committedEffects(runId)` projection over `journal`: successful `remember` is an exact “DELTA.md updated” fact; other successful calls whose `ToolDef.readonly !== true` are honestly described as “potentially mutating calls completed before the cap.” `readonly` is already the fail-closed effect marker (`src/tools.ts:60-75`), and journal status/results survive resume (`src/run.ts:1156-1168`, `src/run.ts:1264-1272`). Deduplicate names and cap the list.
3. Example suffix: `Durable work completed before the stop was not rolled back: DELTA.md was updated; calls: foo, bar.` This is error-as-value: both the failure and partial commit are true.
4. Todo needs no write flush. `writeTodo` commits directly to `thread_state` on every tool call, and `finalize` does not touch it (`src/db.ts:432-477`). Do not clear it. If a saved plan is non-empty, add the qualitative sentence `The working plan remains saved for continuation.` to the failure value.

Do not attempt generic rollback in 0.2.7. MCP/external tools have no transaction shared with SQLite, a timed-out tool may commit after Delta returns, and compensating actions would be tool-specific. The existing timeout value already says “may still complete”; preserve that honesty (`src/run.ts:1186-1239`).

## 4. DESIGN — resilience trio

**VERDICT: FIX, with three small additions rather than a new retry subsystem.**

Targeted competitor findings:

- Pi refuses **all** tool calls in a response stopped for length, even when salvaged JSON parses, because syntactically valid data may still be incomplete (`~/delta/.refs/pi/packages/agent/src/agent-loop.ts:208-214`, `:376-407`). This is the key missing guard.
- Hermes distinguishes syntax repair from execution-time parsing, but its last-resort replacement with `{}` can turn a malformed mutating call into a real empty-argument call; do not copy that fallback (`~/delta/.refs/hermes-agent/agent/message_sanitization.py:185-279`, `agent/tool_executor.py:101-117`).
- OpenClaw bounds its repair buffer at 64K and opts known format repairs into retry explicitly, but its large parser is disproportionate here (`~/delta/.refs/openclaw/src/agents/embedded-agent-runner/run/attempt.tool-call-argument-repair.ts:13-23`, `:700-769`; `docs/concepts/model-failover.md:174-184`).
- Pi's retry classifier puts quota/billing exhaustion ahead of generic 429/transient matching (`~/delta/.refs/pi/packages/ai/src/utils/retry.ts:7-26`, `:83-97`). Hermes makes moderation/content-policy deterministic and non-retryable (`~/delta/.refs/hermes-agent/agent/error_classifier.py:24-73`, `:383-428`).

### 4a. Truncated-tool-call guard

Already present: all three provider streams reject a non-terminal EOF as an error-as-value (`src/provider.ts:904-922`, `src/provider.ts:1259-1282`, `src/provider.ts:1534-1553`), and `execCall` catches invalid argument JSON and returns a useful tool error rather than throwing (`src/run.ts:1196-1241`).

Missing: a provider can report `length`/`max_tokens` with a tool call whose JSON is valid but whose last value/list was cut at a valid boundary. Delta will execute it today.

Implementation sketch:

```ts
// provider.ts
export const outputCapped = (reason: string) =>
  /^(length|max_tokens|max_output_tokens|model_length)$/i.test(reason);
```

1. Preserve Responses API incomplete detail: when handling `response.incomplete`, set `finishReason` from `response.incomplete_details?.reason` rather than leaving it as `tool_calls` (`src/provider.ts:1507-1517`, `src/provider.ts:1556-1571`). Chat Completions and Anthropic already retain their finish/stop reasons (`src/provider.ts:865-895`, `src/provider.ts:1238-1245`).
2. In `executeRun`, after a successful model result and before journal intents are inserted, if `outputCapped(result.finishReason)` and any tool calls exist, persist the assistant row plus one synthetic `[tool error] ... output cap ... reissue a smaller/chunked call` result per call, with matching journal rows already `done`. Do not call the tools (`src/run.ts:980-1016`). Persisting the skip, rather than holding an in-memory flag, makes crash/resume safe.
3. Continue the loop normally so the model can issue a smaller call. Charge the original usage and step exactly as today.
4. Keep invalid-JSON handling as a tool result when the provider did not report an output cap. Give it class `tool_args_invalid`, and make `breakerKey` return `null` for that class: malformed model output does not prove the target tool is categorically dead (`src/run.ts:1037-1119`).

Tests: output-cap + parseable arguments never executes; output-cap skips every call in a parallel batch; invalid JSON is a value; Responses `incomplete_details.reason=max_output_tokens` reaches the guard; resume does not execute a skipped call.

### 4b. One bounded repair attempt

Put the repair at the only execution boundary, immediately around the existing `JSON.parse` in `execCall` (`src/run.ts:1194-1241`). Do not spend another model call and do not repair independently in three provider parsers.

```ts
function parseToolArgs(raw: string): { args?: Record<string, unknown>; repaired: boolean } {
  const parseObject = (s: string) => {
    const v = JSON.parse(s);
    return v && typeof v === "object" && !Array.isArray(v) ? v : undefined;
  };
  try { return { args: parseObject(raw || "{}"), repaired: false }; } catch {}
  if (raw.length > 64_000) return { repaired: false };
  const fixed = escapeLiteralControls(raw).replace(/,\s*([}\]])/g, "$1");
  try { return { args: parseObject(fixed), repaired: fixed !== raw }; } catch {}
  return { repaired: false };
}
```

This is one deterministic repair pass. It preserves data while fixing two common syntax-only defects. Do **not** close missing braces, truncate to a balanced prefix, convert Python literals, rewrite quotes globally, or fall back to `{}`; those can disguise genuine truncation and authorize a different mutating call. If repair fails, use the current error-as-value path. Optionally add a boolean `args_repaired` attribute to the existing `tool.result` event; no new event system is needed.

Also validate that parsed arguments are a non-array object. The current TypeScript cast accepts `null`, arrays, strings, and numbers at runtime (`src/run.ts:1196-1198`).

### 4c. Provider/tool error classification

Do not build a Hermes-sized taxonomy. Delta already has provider status retry/failover (`src/provider.ts:131-139`, `src/provider.ts:341-348`, `src/provider.ts:555-646`), tool error classes + a categorical breaker (`src/run.ts:1037-1147`), and an exporter allowlist for `error.class` (`src/exporter.ts:43-74`). The duplication today is `classifyRetryError` in `run.ts`, which labels telemetry but does not decide behavior (`src/run.ts:1037-1047`).

Add one exported pure classifier in `provider.ts` and make both behavior and telemetry call it:

```ts
type ProviderErrorClass = "moderation" | "quota" | "auth" | "transient" | "request";

function providerErrorClass(status: number | undefined, text: string): ProviderErrorClass {
  if (CONTENT_POLICY_RE.test(text)) return "moderation";        // before 403/429
  if (QUOTA_BILLING_RE.test(text)) return "quota";              // before generic 429
  if (status === 401 || status === 403 || status === 409) return "auth";
  if (status === 408 || status === 429 || (status ?? 0) >= 500 || RETRIABLE.test(text))
    return "transient";
  return "request";
}
```

Behavior mapping:

| Class | Same provider/model | Next provider | Turn |
|---|---|---|---|
| `moderation` | no retry | no failover | terminal value |
| `quota` | no retry / no next model | fail over immediately | fail if none |
| `auth` | retain today's one re-mint, then fail over | yes | fail if none |
| `transient` | retain bounded retry/backoff | after exhaustion | fail if none |
| `request` | no retry | no failover | terminal value |

Use narrow, provider-observed moderation phrases (`content_filter`, `responsibleaipolicyviolation`, `violates our usage policies`, `flagged by ... safety`) and quota phrases (`insufficient_quota`, `quota exceeded`, `billing`, `out of budget`, `available balance`). Do not classify the generic word `policy`. Run's overflow compaction remains a separate recovery path and must be checked before terminal presentation (`src/run.ts:861-896`). Emit the class on retry **and terminal model-error** events so the existing exporter actually carries it.

Tool errors should keep their existing taxonomy/breaker. Only add the two model-output classes (`tool_args_invalid`, `tool_args_truncated`) and exclude them from tool quarantine; merging provider and tool recovery would add coupling without value.

## 5. Safe-mode boot and self-file revert

**VERDICT: FIX (safe mode needs a genuinely separate boot path); self revert already exists.**

Normal boot currently builds all builtins, attaches refresh credentials, connects every MCP server, then loads DELTA.md/POLICY/PROMPT_CONTEXT before binding the server (`src/index.ts:38-100`, `src/index.ts:270-324`). Per-run execution also reloads DELTA.md and grants self-write from the selected profile (`src/run.ts:265-295`, `src/run.ts:440-464`). Merely changing `cfg.profile` is therefore insufficient.

Lean safe-mode wiring:

1. Add `safeMode: boolean` to `Config` and parse `DELTA_SAFE_MODE === "1"` at the top of `loadConfig` (`src/config.ts:19-129`, `src/config.ts:131-180`).
2. In config resolution, safe mode forces `profile: "safe"`, `mcpServers: []`, `allowSelfWrite: false`, `reflect: false`, no hydration/search, and skills `off`. Crucially, do not parse/connect optional MCP or skill config on this branch. Use neutral vocab rather than a workspace vocab file. If the promise is “broken config cannot wedge boot,” also ignore optional model headers/provider fallbacks in this branch; the primary model URL/key/model are the irreducible inputs.
3. Pass `safeMode` into `Deps`. In `executeRun`, select a cloned safe floor directly and skip both `getProfile` env overrides and `grantSelfWrite`; otherwise `DELTA_ALLOWED_TOOLS` can expand recovery mode (`src/run.ts:265-270`, `src/profiles.ts:96-111`).
4. In `loadIdentity`, safe mode sets only `primaryModel`; skip DELTA.md, POLICY.md, and PROMPT_CONTEXT.md (`src/index.ts:103-134`). Skipping only `## Learned` still trusts a poisoned persona and is not neutral. Skipping all workspace prompt layers also avoids an oversized POLICY boot failure. The safe tool envelope is the recovery authority.
5. Guard the refresh/MCP block in `index.ts` rather than relying only on an empty array, making “no MCP handshake” obvious and testable (`src/index.ts:270-322`). Bind the server and recover queued work under the safe envelope as usual.

Do not silently activate safe mode on a normal boot failure; it must be an operator-selected flag and visibly logged/status-reported.

Self revert needs no new storage or agent tool. `self_revisions`, bounded retention, and undoable `revertSelf` already exist (`src/self.ts:162-189`), and the authenticated/loopback Cockpit exposes revision list + revert (`src/server.ts:278-310`). The leanest 0.2.7 action is to reuse and document that surface. Do **not** put `revert_self` in the safe profile: that would turn operator recovery into a model-driven mutation available to untrusted chat input.

If a CLI is required, make `delta self revisions` / `delta self revert <id>` a thin HTTP client of the existing endpoints, not a second direct-DB implementation. It then reuses inspect authentication, validation, atomic write, and the daemon's single-writer discipline. Keep `DELTA_INSPECT_WRITE=1` (or an equivalent explicit operator gate); safe mode must not silently enable root writes.

Correctness/documentation traps:

- `src/self.ts:10-11` still says “No CAS / last-writer-wins,” but `writeSelf` now has an optimistic base-content conflict check (`src/self.ts:102-135`). Update the comment when implementing; the code is the correct behavior.
- The server comment calls revert a “no-gate safety net,” but the route is correctly behind inspect auth and the write opt-in (`src/server.ts:201-225`, `src/server.ts:293-310`). Do not weaken that gate.

## 6. DESIGN — local skills backend (use-only)

**VERDICT: SIMPLIFY the adapter, but FIX the interface's read/write conflation.**

The current `CapabilityAdapter` requires `health`, `search`, `get`, and `propose` (`src/adapters.ts:47-65`). Retrieval calls `search`, auto-loads rank 1 through `get`, and injects the body ephemerally (`src/retrieval.ts:25-62`). Reflection treats `health() === "bound"` as both readable and writable, then stages/promotes procedures (`src/reflect.ts:133-157`, `src/reflect.ts:269-326`; `src/promote.ts:110-161`). A local adapter that reports bound but returns `error` from `propose` would therefore create a five-attempt promotion failure loop. Returning unbound would disable retrieval. That is the main design trap.

### Proposed minimal contract

```ts
export type SkillRef = {
  name: string;
  description?: string;
  version?: number;
  location?: string; // workspace-relative SKILL.md; absent means adapter-loaded body
};

export interface CapabilityAdapter {
  readonly binding?: string;
  health(): RoleHealth;
  search(query: string, ctx: ToolCtx): Promise<SkillRef[]>;
  get(name: string, ctx: ToolCtx): Promise<{ version: number; body: string } | null>;
  propose?(p: SkillProposal & { idempotencyKey: string }, ctx: ToolCtx):
    Promise<"ok" | "error">;
}
```

Making `propose` optional is smaller and more truthful than adding a second health enum or a fake error implementation. Existing `SkillRegistryAdapter` remains unchanged except for satisfying the optional method (`src/adapter-defaults.ts:26-63`). Reflection may search any bound adapter, but stages a `procedure` promotion only when `cap.propose` exists; `drainOnce` checks again before claiming a capability row. This avoids both authoring and retry noise.

### `LocalSkillsAdapter`: exactly what it implements

Place it in `src/adapter-defaults.ts` unless it grows beyond roughly one screen; then use `src/local-skills.ts` and keep the factory in adapter-defaults.

- `binding = "local-skills-v1"` — distinct from today's `skills` binding, so old MCP outbox rows cannot cross the rebind (`src/promote.ts:34-53`).
- `health()` — `bound` when `<workspace>/skills` is a readable directory, otherwise `unbound`; never `unreachable` for a static local tree.
- `search(query)` — enumerate only direct `skills/<dir>/SKILL.md` files; reject symlink/non-directory entries; read only a bounded frontmatter prefix; require a simple scalar `name` and `description`, validate kebab-case name and preferably require it to equal `<dir>`. Score lowercase query words against **name + description only**, positive matches first, deterministic name tiebreak. Return `{name, description: cappedDescription, version: 1, location: "skills/<dir>/SKILL.md"}`. No embeddings, watcher, index DB, or YAML dependency.
- `get(name)` — validate through the indexed names, then read that one SKILL.md on demand, strip frontmatter, and return `{version: 1, body}`. This satisfies the neutral interface for non-model callers; normal local retrieval should not call it automatically.
- No `propose` method. Local is use-only in 0.2.7.

Support only the agentskills.io subset Delta needs: a leading `---` frontmatter block with one-line `name:` and `description:` fields. Skip malformed/oversized entries as error-as-value. Do not implement general YAML.

### Progressive disclosure and selector wiring

1. In `retrieveSkills`, when a ref has `location`, render only its name, bounded description, and `Read <location> with read_file before acting`; do not call `capability.get` and do not say `skill_get`. MCP refs (no location) keep today's rank-1 inline body behavior (`src/retrieval.ts:36-59`). Bundled references/data/scripts remain outside the prompt until `read_file`; scripts use the existing `code` tool. No new read/exec tool is needed.
2. Add `skills: "mcp" | "local" | "off"` to `Config`; parse `DELTA_SKILLS`, warning and falling back to `mcp` for an unknown value. Default `mcp` preserves behavior (`src/config.ts:19-129`, `src/config.ts:227-310`).
3. `buildDeps`: `mcp` leaves `deps.capability` absent, preserving the current per-run `SkillRegistryAdapter(allowedMap)` and its profile filtering (`src/run.ts:466-477`). `local` installs `new LocalSkillsAdapter(cfg.workspace)`. `off` installs an explicit unbound adapter or a mode flag; do not use `undefined`, because `undefined` means “construct the MCP default” today.
4. For `local` and `off`, remove only the known skill-registry MCP tool suffixes from `deps.tools` after MCP registration. Otherwise `skill_get/create/update/...` remain searchable/callable despite the selected backend. Put the exact-name/suffix predicate in `skill-registry.ts`, next to its existing verb matching (`src/skill-registry.ts:12-27`).
5. `off` must also skip `retrieveSkills` entirely and remove `skill_improvement`/skill-index prose from reflection. Add the selector to `Deps`/`ReflectDeps` for that one branch; a merely unbound adapter is not “no mention,” because the current reflection system always describes skills (`src/reflect.ts:50-73`).
6. In `reflect`/`promote`, gate capability authoring on `typeof cap.propose === "function"`. Local procedures can remain governed local memory, but no promotion row targets the local tree. Do not add a local authoring tool, file mutation, hot reload, version store, or promotion format in 0.2.7.

Tests: metadata-only search; body absent from assembled prompt; `read_file` path hint; malformed frontmatter skipped; traversal/symlink rejected; local has no propose; local/off hide MCP skill tools; off produces no skill text in the run or reflection; default mcp behavior remains byte-for-byte equivalent.

## 7. Status read surface

**VERDICT: FIX the current `GET /v1/status`; keeping it separate from `/healthz` is correct.**

`/healthz` is intentionally open and data-free, while every `/v1/*` route passes the control-token gate (`src/server.ts:175-183`, `src/server.ts:350-351`). Model/provider/profile/usage are operational data, so extending health would weaken that contract. The current in-progress `/v1/status` correctly sits after that gate and explicitly selects from the safe config view. It does **not** yet implement the requested contract: it returns a nested `model` object plus `mcp_servers`, but no top-level `effort`, no model-provider cascade, and no `usage` (`src/server.ts:353-368`). MCP servers are tool backends, not model providers. The config view now has the effective budget but still contains only the primary provider's model block (`src/config.ts:329-357`).

Minimal shape:

```json
{
  "model": "configured/primary-name",
  "effort": "high",
  "providers": [{"name":"primary","models":["configured/primary-name"]}],
  "profile": "trusted",
  "budget": {"maxSteps":100,"maxTokens":2000000,"maxCostUsd":5},
  "usage": {"status":"running","steps":7,"tokens":1234,"costUsd":0.02}
}
```

Implementation plan:

1. Replace the reuse of the broad Cockpit config shape with an explicit, already-redacted `status` callback/value on `createServer` opts; construct it in `index.ts` from `cfg.providers.map(({label, models}) => ...)`, top-level `cfg.reasoningEffort`, canonical effective profile/budget, and optionally one run row. Never pass through provider objects, base URLs, headers, credentials, or env (`src/index.ts:334-357`).
2. Keep `GET /v1/status` immediately after the `/v1` auth gate (`src/server.ts:350-368`). Keep it read-only. Returning version/agent id as extra fields is harmless, but match the requested top-level names rather than making Connect know the Cockpit's nested config shape.
3. Make live usage addressable: `GET /v1/status?run=<response_id>`. Apply the same `mayAccess(queue.owner(id), principal)` check as task status and return the same 404 for absent/foreign runs (`src/server.ts:491-535`). Parse the run's persisted usage and steps; fresh tokens are `max(0, input-cacheRead)+output`, matching the actual budget guard. Derive that run's effective profile from its request metadata so a narrowed run is not reported against the daemon ceiling.
4. Without `run`, return the static fields and `usage: null` (optionally queue counts separately). Do not choose an arbitrary “current run”: concurrency defaults above one and a singular usage object would be misleading (`src/queue.ts:274-295`).
5. Define `model` as the configured primary for `/model`. The actual served fallback is only known per completed call/run and already appears in model events/final response; do not call that global state.

Provider labels and model names are safe. URLs are unnecessary, and keys/tokens must never be selected or serialized.

## Release compatibility summary

- Existing `DELTA_PROFILE=work` deployments: **no tool or budget break** with the alias resolver. Add a regression test and keep the default trusted.
- Potential observable migration: canonical profile name becomes `trusted`; do not make string identity part of an old response contract accidentally.
- `DELTA_ALLOWED_TOOLS` replacement semantics can expand a safe tier; either change to intersection or document it loudly. Safe mode must bypass it regardless.
- Default `DELTA_SKILLS=mcp` preserves today's capability retrieval and promotion. `local` and `off` must be explicit.
- No proposed item requires a runtime dependency.
