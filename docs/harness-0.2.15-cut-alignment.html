The headline: their two biggest speed asks were shipped weeks ago

Aperture's board leads with speed: R1 (suspend-safe resume) and R2 (a first-turn heartbeat). Both verdicts came back the same way — the engine work landed in v0.2.4 and has been running on their fleet all period, unexercised. The lease renew-or-reacquire fix (6e36b99, changelog credits "Aperture A2") and the full progress feed — turn.start before every model call, SSE /v1/tasks/:id/events with a coarse mode, a cursor-paged JSON poll labeled "A1" in the source — are all in the released package they run today. R7's proximate failure is likely their own MCP server not setting readOnlyHint, which fail-closed excludes their data tools from sub-agents (mcp.ts:327).

The consequence for the demo window: the biggest speed wins this week are host wiring and config — zero engine risk, no release. The engine release spends its risk budget where the report's real defects are: accuracy and memory quality.

The defect worth drawing: compaction measures the leak, then ships it

Codex's opinion, and what it changed

A high-effort adversarial pass (2.9 M tokens, session 01a0196c…) over the triage and the code. Its verdict, verbatim: "No: four of the five additions are riskier than LOW as currently specified." I verified its factual claims independently before accepting — both hard ones checked out.

accepted A-5 demoted to 0.2.16

The previous-response-id chain is per-run state, but the provider closures are shared across runs (index.ts:59); the id must advance only on successful attempts across the retry/model-hop cascade; the beta header must compose with fast mode; the utility lane must be isolated. That is exactly the CachePlan shape — it belongs in the provider-controls batch. Interim: run the diagnosis beta out-of-band against captured Ferni payloads; the defect investigation does not wait.

accepted A-3 demoted to 0.2.16

Auto-activate changes execution semantics, not just residency: a model could execute a side-effecting allowed tool from a guessed name without ever seeing its schema — search_tools currently provides argument grounding. And A-2 makes the class measurable first. Measure, then fix.

pushed back A-4 split, not dropped

Codex wanted A-4 deferred entirely. Half of it is safe and precedented: writeSelf returns structured {current, overBy, cap}, rendered into the model-facing message only by the remember tool (the Cockpit endpoint keeps its short error). self_conflict already embeds the current file, and the breaker classifies self_cap by prefix before any embedded text. The hollow half — the overflow-path promise — waits for the R3d rail, exactly as Codex argued: profiles with remember but no write_file can't honor it.

accepted A-1 / A-2 hardened

A-1: byte-bound the identifiers individually and in aggregate; reserve appendix bytes inside SUMMARY_CAP; build the final row before the shrink gate. A-2: add tool.rejected to the exporter's payload-event set and export only a closed reason enum — the raw model-controlled tool name must not leave the box with payload capture off (exporter.ts:41).

corrected Ship version: v0.2.4

R1/R2 shipped in v0.2.4, not 0.2.10 — my tag listing was truncated by lexical sort (v0.2.10 sorts before v0.2.4). Verified with merge-base. The verdict is unchanged; the history is now right.

accepted D-5 does the complete fix

Stat the individual SKILL.md files instead of the parent directory mtime — the directory version documented a miss on re-description, the exact case operators expect the feature to catch.
Codex, on R2's mechanics
"Task SSE replays nothing … A client that POSTs and then opens SSE can miss both [run.enqueued, run.started]. Its next guaranteed signal may be the 15-second comment heartbeat, not 1–2 seconds. … The cursor poll from since=0 is reliable."

Where the impact actually comes from: two lanes

no release  Speed — this week, host-side, demo-critical

  • R2 wiring (Aperture): poll /v1/tasks/:id/events from since=0, then tail the SSE. First user signal: 43 s → seconds. Zero engine risk.
  • R7 annotation (Aperture): set readOnlyHint: true on their read-only MCP tools; verify with one spawn on a bench lane. Potentially their largest latency lever.
  • R1 soak (Aperture, config): flip speed-lab to Fly suspend; watch lease + first-turn events for the week. Production stays stop-mode until green.
  • QS config canary (ours): DELTA_TOOL_ARG_MAX_BYTES=4096, DELTA_CACHE_TTL=1h, self-cap raise.
  • Demo day (their plan, endorsed): machine kept started, credits pre-checked, room pre-opened. Nothing engine-side rushed inside the window.

0.2.15  Accuracy & quality — where the release spends its risk

  • Nine Delos items (unchanged): ask-pin D-1 first, exhaustion handoff D-9-min, tool usability, codex output cap, scratch dir, four one-diffs.

Riding to 0.2.16 (the OpenAI-native release)

The provider-controls batch (CachePlan / ModelControls / ReasoningCarry, M1–M5) now also carries: A-5 cache-diagnosis pass-through (it needs exactly the per-run wire state that batch builds) · A-3 named-tool auto-activate, designed with the R7 parity question · R5 sticky provider health, billing-class first · R3c distill-on-refuse as a canary on their volunteered lanes · R8 utility-tier cache marks. R3d (the scoped memory rail — the design all three lanes already built in userspace) is the roadmap item behind the whole R3 family.
