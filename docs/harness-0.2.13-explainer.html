The one-minute version

What this is really about

Every time an agent takes a turn, it re-reads the entire conversation from the beginning. There is a discount for the part that has not changed. We were losing that discount, badly, and we could not work out why.

Delta Harness is the engine that runs our working agents. It sits inside a machine, holds one agent's loop, and talks to a model. Aperture runs eight of them doing paid client work. Ferni runs one on Telegram. Quarry Brain runs more.

The model charges for every token it reads. Because the whole conversation is re-sent each turn, a long job would be ruinous, except that providers offer a prompt cache: if the beginning of your request is byte-for-byte identical to last time, that part is roughly ten times cheaper. Get it right and a long engagement is affordable. Get it wrong and you pay full price for the same words, over and over.

Our biggest consumer measured that on some turns the discount vanished completely. Those turns cost 5.7 times a normal turn and ate 87% of the bill for that window. They also spotted a pattern: it happened exactly when the conversation came out shorter than the turn before.

So everyone, us included, went looking for what makes a conversation shrink. That was the mistake.

The mistake, in one image

We kept weighing the suitcase

Imagine checking whether someone has tampered with a suitcase by putting it on a scale. If they take something out, the weight drops and you catch it. If they swap a book for a different book of the same weight, the scale reads exactly the same and you notice nothing.

The prompt cache does not care what your request weighs. It cares whether it is the same. A change that keeps the size identical breaks the discount just as completely as a change that removes half of it, and every counter anyone proposed, on both sides, would have been blind to it.

That is the whole idea behind this release. Before we fix the leak, we fit a gauge that can actually see it. The gauge is small, it costs almost nothing to run, and had it existed six months ago this entire investigation would have been a single database query.

How a turn is actually built

Four parts, and only two of them can hurt you

Every request the engine sends is assembled in the same order, and the cache reads it strictly left to right. It matches the longest run of identical material starting from the very first byte, then stops at the first difference. Everything after that point is charged at full price.

That ordering is the entire game. A block near the front is load-bearing for every block behind it. A block at the very end can change however it likes.

Technical layer

The wire, the seams, and the falsifiable claim

Everything below is checkable against the repository at the cited lines. Nothing here relies on a consumer's account of their own logs.

Assembly order

The final message list is built once per step and sent whole:

// run.ts:922 — the order is the cache contract
messages = [ system, ...withImages/*history*/, ...ephemeral ]
chat({ messages, tools, cacheKey: session_id, ephemeralCount })

// on the wire, cache matching runs strictly left to right:
//   [ spine ][ tool schemas ][ ......... history ......... ][ fresh ]
//     ^ any change here invalidates everything to its right
//                                                             ^ free to churn

ephemeralCount is what 0.2.11 added so the rolling breakpoints skip the trailing derived blocks. That fix is why the fresh blocks are exonerated here rather than being suspect number one.

The prediction, written before the data

On miss turns, spine_hash moves.

The spine is rebuilt every turn at run.ts:762 and embeds searchable: allowedMap.size − active.size, a counter that decrements on every tool activation, alongside the self-file that the agent rewrites through remember. Both produce cache-fatal, byte-invisible changes to a block sitting at position zero.

If it holds: the fix is to move volatile counters out of the cached prefix. Small, obvious, and it should move the affected lanes into the band above.

If it does not: both prefix hashes stable across a miss means the shrink is inside history, which is append-only outside compaction, and compaction is already ruled out. That would be a defect not currently nameable from source, and knowing it with certainty is worth more than a third theory.

Why identity has to be a hash and not a diff

A diff would answer the question completely and cost far too much: it needs the previous request retained in memory or on disk, it moves model-visible and potentially personal text into telemetry, and it only works on a lane where someone has deliberately turned capture on before the interesting turn happens. A short hash of each segment is a handful of bytes, carries nothing readable, is safe to export without payload consent, and answers which segment with certainty. It cannot answer which byte, which is exactly the follow-up that a targeted capture on a known-guilty segment can then answer cheaply.

That two-stage shape is the general pattern worth taking away: ship the cheap always-on signal that localises, keep the expensive one for confirming. The mistake in this thread was having neither.

Where the route matters

The harness speaks three wire formats, and they do not share cache mechanics. Anthropic-native takes explicit breakpoints, so placement is a lever we control and 0.2.11's fix was aimed there. OpenAI-native matches the longest stable prefix automatically with no breakpoint control at all. OpenRouter inherits whatever the upstream provider does and reports the result in a usage chunk. The instrument is deliberately route-independent, because it measures our own assembled request rather than the provider's response, which means for the first time the same number is comparable across all three. That is also what makes it useful to the benchmark rig, where averaging a cache effect across routes would hide the very thing being measured.

Honesty ledger

What would make this wrong

  • The spine is stable on miss turns. The headline prediction fails and the leak is somewhere we cannot currently name from source. The instrument still pays for itself; the mechanism tier does not land in this release.
  • Misses turn out to be unavoidable. If a large share of them are cold starts after suspend, or genuine first turns, the recoverable band shrinks toward the bottom of the 50-72% range or below it.
  • The window floor is wrong. 249,127 accepted with zero overflow is a field observation, not a published number. Seeding the catalogue from it is deliberately conservative, and the clamp is there so a wrong entry degrades loudly instead of turning compaction into overflow.
  • The quarantine fix is not the fix. Ships anyway because it is correct, labelled explicitly so nobody scores it against the bill. The data that motivated it also ruled it out.
  • Nothing here is built yet. Scoped, committed to the repository, and gated behind cutting 0.2.12 first.
